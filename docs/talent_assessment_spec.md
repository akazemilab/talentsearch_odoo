# فهرست تعاملی استعداد — مشخّصات مدل داده، نمره‌گذاری و ورود دادهٔ تاریخی

وضعیت: پیشنهاد (2026-09-29). پس از تأیید مالک، ساخت روی شاخهٔ `talent-inventory` در `talentsearch_odoo`، تمرین روی کلون `ts db`، سپس `ts_ship.sh`.

## ۰. نتیجهٔ بررسی: مدل موجود کافی است، با یک بُعد اضافه
مدل فعلی: `ts.instrument → ts.instrument.version → ts.instrument.factor (+ band) → ts.instrument.item`؛ `ts.attempt → ts.attempt.answer (item, value) → ts.attempt.result (factor, score, band)`. موتور `engine.score()` (S09-V3.0) هر گویه را دقیقاً یک بار می‌خواهد و هر عامل را در یکی از سه باند.
فهرست تعاملی دو تفاوت دارد: (۱) همان ۱۵ گویه **به ازای هر زمینهٔ خودانتخابی** تکرار می‌شود؛ (۲) تفسیر **نسبی** است (بدون باند). هیچ‌کدام مدل موازی نمی‌خواهد: یک مدل کوچک `ts.attempt.field` + یک کلید `field_id` روی پاسخ و نتیجه + یک موتور خواهرِ جدا (`engine_matrix.py`) کافی است. موتور S09 و ۳۶ سنجهٔ موجود دست نمی‌خورند.

## ۱. تغییرات مدل (ماژول جدید `ts_talent`، وابسته به `ts_assessment`, `ts_org`)
| مدل | تغییر | توضیح |
|---|---|---|
| `ts.instrument.version` | `mode` Selection `single`(پیش‌فرض)/`matrix`؛ `field_min`=2, `field_default`=3, `field_max`=8؛ `field_suggestions` Text (هر خط یک چیپ)؛ `noise_gap` Float=10 | فقط نسخه‌های `matrix` موتور جدید را می‌گیرند |
| `ts.instrument.factor` | `kind` Selection `scale`/`composite`؛ `group` Selection `intelligence`/`action`/`none`؛ `composite_of` Char (کدهای عامل، با کاما)؛ `program_text` Text | ترکیب‌ها گویه ندارند؛ در `matrix` باند لازم نیست |
| **`ts.attempt.field`** (جدید) | `attempt_id`, `sequence` 1..8, `label` Char(80) required, `label_norm` Char (نرمال‌شده برای جستجو), `state` draft/done, `started_at`, `finished_at`, `seconds` Int, `flag_straight` Bool, `flag_fast` Bool, `source_ref` Char | یک ردیف = یک زمینهٔ نام‌گذاری‌شده |
| `ts.attempt.answer` | `field_id` M2o (nullable, ondelete cascade)؛ یکتایی `(attempt_id, item_id, field_id)` به‌جای `(attempt_id, item_id)` | برای سنجه‌های فعلی NULL می‌ماند |
| `ts.attempt.result` | `field_id` M2o nullable؛ `band` غیرالزامی برای `matrix` | `field_id=NULL` = ردیف «میانگین» بین‌زمینه‌ای |
| `ts.attempt` | `profile_json` Text (خروجی تفسیر، برای گزارش و بازتولید)؛ `source` Selection `web`/`import`؛ `source_ref` Char (شناسهٔ فرم‌افزار، یکتا)؛ `import_batch` Char | `user_id` برای رکوردهای `import` **غیرالزامی** و `partner_id` واقعی (compute+inverse) — نیاز به تصمیم مالک (§۷) |
| `ts.workspace` | بدون تغییر؛ purpose=`education` (نقش‌ها owner/counselor) | مؤسسه = partner شرکت + workspace |

## ۲. تعریف سنجه (داده، نه کد) — `data/talent_inventory.xml`
- Instrument: code `TALENT-INV-15`, slug `talent-inventory`, title «فهرست تعاملی استعداد», category «استعدادیابی», audience `adolescent` (پیشنهاد؛ مسیر guardian موجود فعال می‌شود — تصمیم مالک)، purpose `personal`, `intended_use/limitations/evidence_note` از متن کتاب (بخش ۵ خلاصه) و پژوهش B.
- Version `TALENT-INV-15/1.0`: `mode=matrix`, scale 1–5, reverse: هیچ، aggregation «mean×20», missing «هر زمینهٔ نام‌دار باید ۱۵ پاسخ داشته باشد».
- ۱۵ گویه عیناً از سرستون‌های فرم‌افزار (`docs/talent_items.json`، md5 `9afb7ade…`)؛ گویهٔ i ← عامل `(i-1) mod 5`.
- ۵ عامل `scale` (کد/نام رسمی طبق تیترهای کتاب L274–L283): `ANA` هوش تحلیلی، `EXP` هوش تجربی، `ACA` هوش تحصیلی (group=intelligence)؛ `NOV` کنش نوسودمندی، `DUT` کنش وظیفه‌مندی (group=action). `definition` = تعریف عیناً کتاب.
- ۷ عامل `composite`: `TOT` کل=ANA,EXP,ACA,NOV,DUT؛ `INT` هوش=ANA,EXP,ACA؛ `ACT` کنش=NOV,DUT؛ `CRE` خلّاقیّت=ANA,EXP,NOV؛ `SCH` استعداد تحصیلی=ACA,DUT؛ `CRT` خلّاقیّت نظری=ANA,NOV؛ `CRP` خلّاقیّت عملی=EXP,NOV. (L564–L566)
- لنگرهای پاسخ (L159): ۱ بسیار کم · ۲ کم · ۳ متوسط · ۴ زیاد · ۵ بسیار زیاد.

## ۳. موتور `engine_matrix.py` (توابع خالص، تست طلایی بدون ORM)
```
score_matrix(contract, fields) -> {fields:[{seq,label,scales:{code:score},composites:{...},flags}],
                                   mean:{code:score}, input_hash, output_hash, engine:'TS-MATRIX-1.0'}
```
- ورودی هر زمینه: ۱۵ پاسخ صحیح در [1,5]، دقیقاً یک بار؛ کمتر → `ScoringError` (زمینهٔ ناقص ذخیره نمی‌شود، نه «صفر»).
- مقیاس = mean(items)×20 ⇔ sum/15×100 (دامنهٔ ۲۰–۱۰۰؛ روی داده تاریخی 100٪ تطابق). ترکیب = میانگین سادهٔ مقیاس‌های `composite_of`. ردیف `mean` = میانگین هر عامل روی زمینه‌ها.
- `interpret(result, noise_gap=10)` → `profile_json` طبق هفت سطح کتاب (L525–L542) با قاعدهٔ تساوی/نویز:
  1. کلّی: `mean.TOT`.
  2. اجمالی: بهترین عامل (بیشینهٔ `mean` روی ۵ مقیاس) × بهترین زمینه (بیشینهٔ `TOT`) → میانگین دو عدد.
  3. ترکیبی: زمینهٔ بیشینهٔ `INT` و زمینهٔ بیشینهٔ `ACT`.
  4. کانونی: بیشینهٔ مطلق در بلوک ۳ هوش × زمینه‌ها و بلوک ۲ کنش × زمینه‌ها → «کنش* هوش* در زمینهٔ تعاملی زمینه* با زمینه**».
  5. تفصیلی: برای هر زمینه (argmax هوش، argmax کنش) → برچسب «X‑مندی Y»؛ برچسب غالب = مُد؛ زمینه‌ها = اجتماع argmax پنج مقیاس. هفت حالت (شش + «ترکیبی»).
  6. نوع استعداد: زمینهٔ بیشینه برای `CRE`, `SCH`, `CRT`, `CRP`.
  7. استعداد ضعیف: کمینهٔ `mean` روی ۵ مقیاس × کمینهٔ `TOT`.
  - **تساوی/نویز**: در هر argmax/argmin، همهٔ گزینه‌هایی که تا `noise_gap` (۱۰ نمره ≈ SE_diff) از بیشینه فاصله دارند با هم گزارش می‌شوند (رفتار کتاب: «علوم - اجتماعی»). با یک زمینه: فقط سطح ۱ و ترتیب توانایی‌های همان زمینه (بدون «برجسته‌ترین زمینه»).
  - پرچم‌ها: `straight` (۱۵ پاسخ یکسان)، `fast` (< ۳۰ ثانیه برای ۱۵ گویه ≈ ۲ ثانیه/گویه). زمینهٔ پرچم‌دار در تفسیر می‌ماند ولی در گزارش با یادداشت.
- سیاست آموزش (L544–L553) و تقویّت (L555–L572) فقط نگاشت متنی روی همان argmax‌ها هستند (`program_text` عامل + قالب‌های ثابت): تحصیلی/وظیفه‌مندی ← «تسریع…»؛ تحلیلی/تجربی/نوسودمندی ← «غنی‌سازی…»؛ ضعیف‌ترین زمینه ← «آموزش جبرانی…»؛ ضعیف‌ترین توانایی ← «پرورش تقویّتی…» (نام‌ها عیناً، بخش ۷ خلاصه).
- `rescore_matches()` موجود برای `matrix` از موتور جدید استفاده می‌کند (بازتولیدپذیری تاریخی).

## ۴. جریان پاسخ‌دهی (کنترلر `ts_talent`)
مسیرها زیر همان `/take/<token>` با `page` = `f<seq>-p<1..3>`:
1. رضایت (قالب موجود؛ guardian اگر audience کودک/نوجوان).
2. راهنمای یک‌صفحه‌ای: «برای هر زمینه ۱۵ جمله، ۵ درجه؛ ۲ تا ۸ زمینه؛ حدود ۱ دقیقه برای هر زمینه».
3. **زمینه**: چیپ‌ها + متن آزاد (الزامی، ≤۸۰ نویسه؛ نرمال‌سازی: حذف فاصلهٔ اضافی، ي/ك عربی → فارسی؛ تکراری بودن نام در همان تلاش رد می‌شود).
4. سه صفحهٔ ۵ گویه‌ای؛ رادیوهای عمودی با لنگر کامل؛ ذخیرهٔ خودکار هر گویه (`/answer` موجود با `field`)؛ «زمینهٔ ۲ از ۳ · صفحهٔ ۱ از ۳».
5. پایان زمینه: اگر ۱۵ پاسخ یکسان → تأیید ملایم یک‌باره. سپس «افزودن زمینهٔ دیگر» / «پایان و دیدن نتیجه» (دومی فقط از زمینهٔ ۲ به بعد فعال).
6. بازبینی → ارسال → گزارش. زمینهٔ ناقص هنگام ارسال حذف می‌شود اگر هیچ پاسخی ندارد، وگرنه کاربر به اوّلین گویهٔ بی‌پاسخ برمی‌گردد.

## ۵. گزارش (`ts_talent.report`, جایگزین `ts_assessment.report` وقتی `mode=matrix`)
ترتیب: خلاصه (۴ کارت با جملهٔ کتاب) → نمودار نقطه‌ای هر زمینه (SVG درون‌خطی، محور ۲۰–۱۰۰، نوار ±۸) → «این یعنی چه / گام بعدی» به ازای برجسته‌ترین‌ها → جدول تعاملی کامل (زمینه × عامل + میانگین + تقویت + آموزش) → پاسخ‌های خام (فقط صاحب تلاش) → دربارهٔ این سنجه و محدودیت‌ها. نمای سازمان (counselor): همان گزارش با `share_level` موجود؛ بدون پاسخ خام مگر full. چاپ: `@media print`, یک ستون، بدون رنگ پس‌زمینهٔ سنگین.

## ۶. ورود دادهٔ تاریخی — `tools/prod/ts_import_talent.py --xlsx F --db DB [--dry-run] [--batch LABEL]`
پیش‌شرط‌ها (assert، وگرنه توقف بلند): DB نام `eot_ts*` یا `eot_main` با `--live` صریح؛ سنجه `TALENT-INV-15/1.0` منتشرشده؛ شیت با ۲۴۷ ستون و همان ۱۵ سرستون؛ partner «مؤسسه تعاملی هیجان اندیشه» ≤ ۱ (0 → ساخته می‌شود، is_company؛ >۱ → توقف)؛ workspace همان partner با purpose=education (یکی).
قواعد:
- کلید یکتا = `شناسه` فرم‌افزار → `attempt.source_ref='formafzar:0ekrq:<id>'`؛ وجود = رد شدن (idempotent).
- شخص: نرمال‌سازی موبایل (E.164 +98) و ایمیل (lower). **پیشنهاد ادغام**: موبایل یکسان → همان partner؛ در نبود موبایل، ایمیل یکسان؛ در نبود هر دو → partner جدا با نام. هر ردیف = تلاش جداگانه (تکرارکننده‌ها دو تلاش دارند). بدون user (تصمیم مالک §۷)، بدون هیچ پیام.
- تاریخ: جلالی «YYYY/MM/DD HH:MM» تهران → UTC (jdatetime؛ تست دوطرفه با `g2j` موجود).
- زمینه: فقط بلوک‌هایی که نام متنی دارند **و** ۱۵ پاسخ عددی ۱–۵ دارند؛ نام عیناً (trim) + `label_norm`؛ بلوک بی‌نام رد می‌شود (شمارش «پیش‌فرض ۳»)؛ نام‌دار ولی ناقص → رد با دلیل.
- وارد نمی‌شود: IP، مرورگر، موقعیت، مشتری اصلی، اپراتورها، پرداخت، ارجاع، همهٔ ستون‌های مشتق.
- پس از ورود: موتور روی هر تلاش اجرا و `profile_json` ساخته می‌شود؛ گزارش بازمحاسبه با ستون‌های مشتق **فقط** برای ۵ مقیاس و کل مقایسه می‌شود (انتظار: تطابق ۱۰۰٪؛ اختلاف → توقف).
- پرچم‌ها: `consent_service=False`, `consent_version='IMPORT-FORMAFZAR'`, `released=False` تا مالک تصمیم بگیرد, `state='done'`, `source='import'`.
- گزارش چاپی: ردیف‌ها، اشخاص ساخته/ادغام‌شده (شمارش)، تلاش‌ها، زمینه‌های واردشده/ردشده به تفکیک دلیل، پرچم‌ها. بدون هیچ دادهٔ شخصی.
- مسیر: کلون → بررسی → live با `--live` و بکاپ قبلی؛ `ts guard` قبل/بعد.

## ۷. تصمیم‌های مالک (یک‌جا پرسیده می‌شود)
1. مخاطب سنجه: نوجوان (مسیر ولی فعال) / بزرگسال / هر دو.
2. شرکت‌کنندگان تاریخی: بدون حساب کاربری (partner فقط؛ بعداً با موبایل تأییدشده قابل «ادعا») **[پیشنهاد]** / ساخت کاربر پورتال بدون دعوت.
3. قاعدهٔ ادغام تکراری‌ها: موبایل، سپس ایمیل **[پیشنهاد]** / هر ردیف شخص جدا.
4. ترکیب‌ها در گزارش: هر هفت ترکیب کتاب **[پیشنهاد]** / فقط پنج مقیاس + کل.
5. حداقل زمینه‌ها: ۲ **[پیشنهاد]** / ۱ (بدون مقایسهٔ زمینه‌ای).
6. انتشار نتایج تاریخی برای صاحبانشان: خیر تا اطلاع بعدی **[پیشنهاد]** / بله پس از ادعا.
